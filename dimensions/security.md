# 安全审查视角

## 检查清单

1. **注入攻击** — SQL/NoSQL/命令注入/模板注入/XSS 向量
   - 用户输入直接拼接进 SQL/Shell/HTML 而未参数化或转义
   - 使用 `eval`、`Function()`、`exec`、`spawn` 且参数含用户可控内容
   - 模板引擎中直接输出未转义的用户数据

2. **认证与授权** — 缺失或可绕过的鉴权检查
   - 敏感端点缺少认证中间件或权限校验
   - 仅依赖客户端传入的角色/ID 进行授权判定
   - Token 校验逻辑存在时序攻击或绕过路径

3. **敏感信息泄露** — 硬编码密钥、日志中的 PII、源码中的凭证
   - API Key、密码、数据库连接串等硬编码在源码中
   - 日志或错误响应中包含用户 PII、内部路径或堆栈信息
   - `.env` 文件被意外提交或敏感配置缺少环境变量隔离

4. **加密缺陷** — 弱算法、不当密钥管理、缺失传输加密
   - 使用 MD5/SHA1 做密码哈希而非 bcrypt/scrypt/argon2
   - 密钥硬编码或与代码同仓库存储
   - 敏感数据通过 HTTP 明文传输

5. **不安全的反序列化** — 未校验的不可信数据反序列化
   - 对外部输入直接使用 `JSON.parse` 后未做 schema 校验即信任字段
   - 使用 `pickle`/`yaml.load`/`unserialize` 处理不可信数据

6. **路径遍历** — 未校验用户输入用于文件操作
   - 用户可控路径参数直接传入 `fs.readFile`/`fs.writeFile` 而未规范化或白名单校验
   - 缺少对 `../` 序列的过滤

7. **SSRF** — 服务端请求伪造
   - 用户提供的 URL 直接传入 `fetch`/`axios`/`http.request` 而未校验目标地址
   - 缺少对内网地址（127.0.0.1、10.x、169.254.x）的过滤

## 严重度判定

- **high**: 允许远程代码执行的注入、硬编码的生产密钥/凭证、敏感端点完全缺失认证
- **medium**: 弱加密算法、过宽的 CORS 配置、内部 API 缺少输入校验、日志中泄露内部路径
- **low**: 缺少安全响应头（CSP/HSTS）、冗余错误信息暴露内部结构、非敏感端点的 rate-limit 缺失

## 维度规则

- 仅报告有代码证据的安全问题，不报告假设性威胁或纯理论攻击面
- 不报告已由框架/中间件统一处理的问题（如 ORM 参数化查询、框架自带 CSRF 防护）
- 对于第三方依赖的已知 CVE，标注但不自动修复（标记为 behavior-risk）
- 评估时考虑部署上下文——内网工具与公网服务的安全要求不同
- 修复风险判定：添加输入校验/转义 = safe；重构鉴权中间件/提取安全工具函数 = local；重新设计鉴权架构/引入加密层 = structural；变更公开 API 的鉴权契约 = behavior-risk
